# US-074b — Token pessoal para clientes sem OAuth (fora do POC)

**Marco:** R4-D (backlog) · **Deps:** US-074, US-075, US-076b · **Estimativa:** a estimar pelo TL · **Status:** blocked (decisão do usuário, D-GES-37; `MCP_ENABLED` desligado)

## Objetivo
Permitir que o membro gere um token pessoal (PAT) para IDEs/CLIs/agentes que não usam OAuth, com o mesmo escopo, limites e revogação das conexões OAuth.

## Contrato técnico essencial
- OAuth continua obrigatório para Claude/ChatGPT hospedados (ADR-030 §2); o PAT só soma clientes sem OAuth. Reusa `McpGrant`/`McpToken` (hash do token, nunca texto claro no banco), `McpAuditEvent`, `MemberAssistantLimits`.
- Única exceção à regra "sem credencial exibida": o token aparece uma vez, com botão copiar; depois só nome, escopo, validade e último uso. Validade obrigatória (sem token eterno); sem rotação automática, risco registrado.
- Escopo padrão `read`; `write` exige a segunda ciência da US-074 e respeita os limites do membro (US-076b: R$ 500, 10/dia, 5/hora por padrão). Revogação imediata; Administrador pode bloquear o recurso; remover o membro revoga. Toda chamada auditada (US-077).
- A especificar pelo TL: rota de criação, formato do token (prefixo identificável para varredura de segredo), tabela ou coluna de tipo de grant.

## Critérios de aceite
1. O token é mostrado uma única vez; reabrir a tela não o mostra.
2. O token nasce só de consulta; incluir lançamento exige a segunda ciência.
3. Token com lançamento respeita os limites do membro (a 11ª despesa do dia é recusada).
4. Revogar o token invalida a próxima chamada imediatamente.
5. Administrador bloqueia o recurso e os tokens deixam de funcionar.
6. O banco guarda só o hash; o log e a auditoria nunca contêm o token (teste).
7. Testes: integração (criação, uso, revogação, bloqueio, limites), E2E da tela.

## Fora de escopo
- Token por família; token sem validade; ponte stdio.
