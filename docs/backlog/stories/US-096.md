## Objetivo
Cadastrar uma assinatura mensal num cartão; no dia da cobrança ela vira compra real na fatura certa, sem o usuário lançar. Telas na US-096c.

## Contrato técnico
- Migrações (expand, ADR-036): (1) `ALTER TYPE "TransactionOrigin" ADD VALUE 'SUBSCRIPTION'` sozinha; (2) `card_subscriptions`, `card_subscription_amounts`, `subscription_charges` + enum `SubscriptionChargeStatus` (colunas do ADR-036; em `subscription_charges` também `isAmended` e `sharedDowngraded` `boolean DEFAULT false`, usadas nas US-097/099); FKs compostas `(familyId, x)`; CHECKs `dayOfMonth 1..31`, `amountInCents > 0`, `endedAt/endedOn/endedByMemberId` juntos, `status='POSTED' <=> transactionId NOT NULL`; únicos `(familyId, subscriptionId, chargeMonth)` e `transactionId`; índice `(familyId, endedAt, nextChargeOn)`. Comentário de reversão no topo.
- `assinaturas/schemas.ts`: `CreateSubscriptionSchema` `.strict()` `{ cardId: uuid, description: 2..100, amountInCents: int 1..9_999_999_999, categoryId: uuid, payerMemberId?: uuid, dayOfMonth: 1..31, startMonth?: "YYYY-MM", end: { type: "NONE" } | { type: "COUNT", count: 1..120 } }`. `SubscriptionDTO` `{ id, card {id,name,archived}, description, category {id,name}, payer: MemberRef, dayOfMonth, currentAmountInCents, firstChargeOn, nextChargeOn|null, endMonth|null, endedOn|null, version, recentSkips: {month, reason}[] (últimos 3) }`.
- `assinaturas/schedule.ts` (puro; reusa `occurrenceDueOn`/`addMonths`/`endMonthFromCount` de `previstas/recurrence.ts`): `chargeDateOf(month, day)`; `firstChargeOn(startMonth, day, today)` = 1º `chargeDateOf(M) >= today` com `M >= startMonth`; `nextAfter(month, day, endMonth)`; `amountFor(month, rows)` (maior `fromMonth <= month`, empate `createdAt` desc).
- `assinaturas/service.ts`: `createSubscription` sob `lockFamilySplit` → cartão ativo da família `FOR SHARE` (senão 422 `INVALID_REFERENCE` `path: cardId`) → categoria de despesa ativa → `startMonth` entre o mês atual e +11 (422 `INVALID_START_MONTH`) → travas de propriedade de compra no cartão de `createExpenseCore` para o pagador (spec 01; mesmo predicado, sem duplicar) → insere série e a primeira linha de valor (`fromMonth` = mês de `firstChargeOn`). `isSharedExpense` sempre false (US-099). `listSubscriptions(status, cardId?)`, `getSubscription`.
- `assinaturas/charges.ts`: `ensureSubscriptionCharges(tx, ctx)` — atalho sem trava (`endedAt IS NULL AND nextChargeOn <= hoje`); senão `lockFamilySplit`, advisory `subscriptions:{familyId}`, relê; para cada assinatura (ordem de id), enquanto `nextChargeOn <= hoje` e até 12 por chamada: mês já em `subscription_charges` => pula; cartão arquivado/excluído => `SKIPPED_CARD_ARCHIVED`; fatura do ciclo (`invoiceRefFor`) com pagamento ativo => `SKIPPED_INVOICE_PAID`; senão `createExpenseCore` e `POSTED`; avança `nextChargeOn` (nulo após `endMonth`). `ensureSubscriptionChargesStandalone(ctx, db)`: uma transação curta por assinatura vencida; erro é logado sem PII e não quebra a leitura.
- `transacoes/service.ts`: opção `subscription: { subscriptionId, authorMemberId }` em `createExpenseCore` => `origin = SUBSCRIPTION`, autor = `authorMemberId`, `allowArchivedCategory`, sem checagem ator × pagador. Ajuste `switch` exaustivos de `origin` que o typecheck apontar (filtro do Extrato aceita `SUBSCRIPTION`).
- Rota `src/app/api/v1/subscriptions/route.ts`: `POST` (`Idempotency-Key`, 201) e `GET ?status=active|ended&cardId=` (chama o Standalone antes da leitura).

## Critérios de aceite
1. Unit `schedule`: dia 31 em fev/2027 => 28/02; 29 em fev/2028 => 29/02; cadastro em 20/11 com dia 10 => primeira 10/12; com dia 20 => 20/11; `COUNT 3` termina no 3º mês; `amountFor` com dois reajustes.
2. Antes do dia nenhuma compra existe; no dia (relógio injetado) a compra aparece com `origin=SUBSCRIPTION`, valor do mês, `occurredOn` = dia da cobrança e fatura do ciclo correto (dia <= fechamento fica no mês).
3. `Promise.all` de 5 `ensureSubscriptionCharges` => uma compra só; excluir a compra no Extrato e rodar de novo não recria.
4. Fatura do ciclo paga => `SKIPPED_INVOICE_PAID`, nenhuma compra, `nextChargeOn` avança; limite usado conta só compras lançadas.
5. Três meses sem abrir o app => três compras, cada uma na sua fatura.
6. Cartão de outra família ou arquivado => 422 `INVALID_REFERENCE`; pagador fora das regras do "Só meu" => mesmo erro da compra no cartão.
7. Testes: unit `tests/unit/assinaturas/schedule.test.ts`; integração `us-096-assinatura-lancamento.int.test.ts` (ACs 2-6).
