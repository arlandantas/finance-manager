# US-046 — Gerenciar tags: listar, renomear, mesclar e remover

**Marco:** R3 · **Deps:** US-045 · **Estimativa:** ≤8 arquivos (3 pts)

## Ler antes (somente estes)
- docs/spec/10-lancamentos-contas-extrato.md
- docs/adr/ADR-022-tags-e-agregado-unico-da-analise.md

## Objetivo
Qualquer membro mantém o vocabulário de tags da família sem mexer em valores nem no acerto.

## Contrato técnico essencial
```ts
TagNameSchema: trim, 2..30 chars ("A tag precisa ter entre 2 e 30 caracteres"), só letras/números/_/./-/espaço
RenameTagSchema { version, name }   MergeTagSchema { version, intoId }   DeleteTagSchema { version }
TagDTO { id, name, usageCount, version, updatedBy }   MergeTagResponse { tag, movedCount }
```
- Rotas (todas `auth: family`, qualquer membro, `Idempotency-Key`): `GET /tags?q=&limit=` (sem `q`: todas por uso desc, nome asc; com `q`: prefixo de `nameKey`, <=500), `PATCH /tags/:id`, `POST /tags/:id/merge`, `POST /tags/:id/delete`. Já existem (US-045): `normalizeTagKey`, tabelas `tags`/`transaction_tags`, `GET /tags`.
- Renomear: atualiza `name`/`nameKey` (a ligação é por `tagId`, então todos os lançamentos mudam); colisão de `nameKey` => 409 `TAG_NAME_EXISTS` com `details { mergeIntoId, mergeIntoName }`. Conflito de `version` => 409 `VERSION_CONFLICT` ("Esta tag foi alterada por {Nome}. Recarregue para continuar.").
- Mesclar (uma transação): travar origem e destino `FOR UPDATE` por `id` crescente; mover ligações com `ON CONFLICT DO NOTHING`; apagar origem; `FamilyEvent(TAG_MERGED)`; origem igual destino => 422 `TAG_MERGE_SAME`. Remover: apaga ligações e tag; `FamilyEvent(TAG_DELETED)`; `removedFromCount` = lançamentos ativos afetados.
- `usageCount` = lançamentos ativos distintos. Nada disso altera `amountInCents`, `occurredOn`, rateio, `ledgerTotals` ou acerto (checksum antes/depois). Tag de outra família => 404.

## Critérios de aceite
1. A tela Configurações > Tags lista nome e "N lançamentos" ordenada por uso (viagem 5, viajem 3, ferias 0); vazia mostra "Nenhuma tag ainda. Crie tags ao lançar uma despesa."
2. Renomear atualiza a tag nos lançamentos; mudar só caixa/acento atualiza `name`; "a" => "A tag precisa ter entre 2 e 30 caracteres".
3. Renomear "viajem" para "Viagem" oferece "Já existe a tag Viagem. Mesclar viajem nela?".
4. Mesclar leva viajem para viagem (8 lançamentos, `movedCount 3`; 7 se 1 em comum), a origem some e o evento é registrado; falha injetada deixa tudo intacto; mesma chave = 1 efeito.
5. Remover viagem mantém os 5 lançamentos sem a tag; tag sem uso some da lista; checksum de `transactions` e `ledgerTotals` idêntico.
6. MEMBER também renomeia, mescla e remove; conflito de versão mostra a mensagem de Mariana.
7. `merge` x `POST` de lançamento com a tag de origem (`Promise.all`) nunca deixa ligação órfã; `merge A->B` x `merge B->A` sem deadlock.

## Fora de escopo
- Cor/ícone de tag; tags em transferência; hierarquia de tags.
