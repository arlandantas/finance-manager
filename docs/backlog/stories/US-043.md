## Objetivo
O interruptor "Dividir" vira seletor de três modos; o percentual escolhido fica gravado no lançamento (a regra da família é só a sugestão).

## Contrato técnico essencial
```ts
SplitInputSchema = discriminatedUnion("mode", [
  { mode: "NONE" }, { mode: "RULE" },                       // RULE = regra vigente em occurredOn
  { mode: "CUSTOM", shares: { memberId, bps }[] (min 2) }]) // soma 10000 ("Os percentuais precisam somar 100%"), sem membro repetido
// Create/Update de despesa e de previsão: split? OU isSharedExpense? (juntos => 400); legado true == RULE
// TransactionDTO.split = { mode, ruleVersionId, shares: {member, bps, amountInCents}[] } | null
// defaults.split.modes ganha "CUSTOM"; SplitExplanationDTO.customSplitCount
```
- `splitAmount(amount, shares, payer)`: piso por bps; sobra de centavos para quem pagou (se bps>0) senão por maior resto/ordinal. Vetores: 5c 50/50 pagador Lucas = 3/2; 9000 40/40/20 = 3600/3600/1800; 20000 100%/0% = 20000/0; 10001 50/50 pagadora Mariana = 5001/5000; propriedade: Σ = total, ordem das shares irrelevante.
- Erros: 422 `SHARES_MEMBER_MISMATCH` (CUSTOM sem todos os ativos), 422 `SETTLEMENT_DISABLED`, 409 `SETTLED_PERIOD_CONFIRMATION_REQUIRED` em mês acertado.
- Previsão guarda `split`; a baixa herda (RULE resolvida na data do pagamento, CUSTOM copiado). Primeira trava de toda escrita: `lockFamilySplit`.

## Critérios de aceite
1. O seletor (radiogroup) mostra "Só meu" (padrão), "Pela regra da família (50% / 50%)" e "De outro jeito".
2. RULE em R$ 300,00 grava 50/50 (15000/15000) e o acerto cota R$ 150,00 para cada; Só meu não entra no acerto.
3. De outro jeito aceita 0% e 100% (Lucas 100%, Mariana 0% em R$ 200,00 = cota 20000/0); soma diferente de 100 mostra "Os percentuais precisam somar 100%" e desabilita salvar.
4. 5 centavos 50/50 pagador Lucas: cota Lucas R$ 0,03, Mariana R$ 0,02.
5. Mudar a regra para 70/30 não altera lançamentos antigos; novos RULE usam 70/30 ("Pela regra da família (70% / 30%)").
6. Três membros 40/40/20 em R$ 90,00 = 3600/3600/1800.
7. Editar o modo em mês aberto atualiza o acerto; em mês acertado exige confirmação (409 até confirmar).
8. Sem acerto ligado o seletor não aparece e `split != NONE` retorna 422.
9. "Só meu" mantém quatro toques.
10. Previsão `CUSTOM` copia o rateio na baixa; `isSharedExpense` + `split` juntos retornam 400.
