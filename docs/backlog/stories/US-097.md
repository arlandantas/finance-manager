## Objetivo
Corrigir o valor de uma cobrança já lançada, reajustar a assinatura a partir de um mês e encerrá-la, sem reescrever o passado.

## Contrato técnico
- **Corrigir a cobrança** = `PATCH /transactions/:id` existente (version, 409, `INVOICE_PAID_LOCKED`). Em `transacoes/mutations.ts`: se `origin = SUBSCRIPTION` e mudou valor, data, descrição ou categoria, `UPDATE subscription_charges SET "isAmended" = true WHERE "transactionId" = id` na mesma transação. Nenhum outro mês muda.
- **Reajustar/editar:** `PATCH /api/v1/subscriptions/{id}` `.strict()` `{ version, description?, categoryId?, payerMemberId?, amountInCents?, effectiveFromMonth?: "YYYY-MM" }` (`assinaturas/manage.ts`), sob `lockFamilySplit` → linha `FOR UPDATE`:
  - encerrada => 409 `SUBSCRIPTION_ENDED`; `version` divergente => 409 `VERSION_CONFLICT` "alterada por {nome}" (`updatedByMemberId`);
  - controle: "Só meu" só quem controla a compra no cartão (titular do cartão/pagador, spec 01, mesmo predicado da edição de compra); troca de pagador passa pelas travas da criação;
  - `amountInCents` => insere `card_subscription_amounts` com `fromMonth = effectiveFromMonth ?? mês de nextChargeOn`; `fromMonth` < mês de `nextChargeOn` => 422 `EFFECTIVE_FROM_ALREADY_CHARGED` ("Esse mês já foi cobrado; corrija a cobrança no Extrato");
  - demais campos valem para as próximas cobranças; dia e cartão não mudam (encerre e crie outra; campo extra = 400);
  - sem diferença efetiva => 200 sem subir `version`.
- **Impacto:** `GET /api/v1/subscriptions/{id}?impactFrom=YYYY-MM` devolve também `impact: { affectedCount: number | null (null = sem fim), keptPostedCount, keptAmendedCount }`; `keptPostedCount` = cobranças `POSTED` já lançadas (nunca reescritas).
- **Encerrar:** `POST /api/v1/subscriptions/{id}/end` `{ version }` (`Idempotency-Key`): antes, roda `ensureSubscriptionCharges` só desta assinatura (cobrança com data <= hoje é lançada e fica); depois `endedAt`, `endedOn = hoje`, `endedByMemberId`, `nextChargeOn = NULL`, `version + 1`. De novo => 409 `SUBSCRIPTION_ENDED`. Reativar = cadastrar nova.
- UI: clicar na assinatura do bloco do cartão abre `subscription-drawer.tsx` em modo edição (valor com "A partir de" mês, aviso do `impact` "Muda N próximas cobranças; M já lançadas ficam"), botão "Encerrar assinatura" com confirmação "As cobranças já lançadas ficam no Extrato"; cobrança "alterada" ganha selo no Extrato.
- Arquivos: `assinaturas/manage.ts`, `assinaturas/schemas.ts`, `assinaturas/hooks.ts`, rotas `subscriptions/[id]/route.ts` (GET, PATCH) e `[id]/end/route.ts`, `transacoes/mutations.ts`, `subscription-drawer.tsx`, `invoice-screen.tsx`.

## Critérios de aceite
1. Corrigir só a cobrança de novembro (55,90 → 59,90) não altera outubro nem dezembro; `isAmended = true` e o selo "alterada" aparece.
2. Cobrança em fatura paga => 422 `INVOICE_PAID_LOCKED`.
3. Reajuste 55,90 → 59,90 a partir de dezembro: cobranças anteriores e "alteradas" ficam; a de dezembro sai por 59,90; `fromMonth` já cobrado => 422.
4. `impact` informa afetadas (null sem fim, N com fim) e mantidas.
5. Encerrar no dia 5 com cobrança dia 10: nada é lançado depois; com cobrança dia 3 não lançada ainda, ela é lançada antes de encerrar.
6. Editar ou encerrar assinatura encerrada => 409 `SUBSCRIPTION_ENDED` com mensagem clara.
7. Duas edições simultâneas (`Promise.all`) => uma 200, outra 409 com o nome de quem alterou.
8. MEMBER sem controle sobre a assinatura "Só meu" alheia => 403 (mesmo código da edição de compra "Só meu").
9. Testes: integração `us-097-assinatura-editar-encerrar.int.test.ts` (ACs 1-8), E2E reajuste e encerrar.

## Fora de escopo
- Pausar; trocar cartão ou dia; alterar cobrança de fatura paga; renegociar em parcelas.
